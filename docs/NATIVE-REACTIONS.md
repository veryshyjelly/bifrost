# Native reactions

Actor-specific WhatsApp reactions and owner Telegram reaction updates are implemented through isolated native SDK/PostgreSQL worker fixtures. Explicit `/react` and `/delete` source commands, source revocation choices and runtime composition remain in [PORT-COMPLETION.md](PORT-COMPLETION.md).

Source reaction state preserves each canonical actor, its emoji, revision and any represented owner echo. A full object snapshot removes absent actors; a partial update changes only its sender. Snapshot object order remains deterministic, including aliases. As in the baseline, non-object snapshot values are ignored and non-string emoji values are filtered. FE0F variation selectors do not create different stored reaction identities. The small legacy mapping of clear Unicode equivalents to Telegram reactions remains in place.

Projection groups retained mappings by private bot scope or group/topic. It prefers the freshest delivery and its attachment over split labels. Available member bots represent their actors; the newest actor assigned to a shared bot determines that bot's reaction. Actor departure clears only the bot reaction that no longer has a desired actor. Private message IDs never cross bot scopes.

Native refusal signatures are cached for one minute. A member bot unable to see a group message can reroute its reaction to the master. Missing primary messages/topics remain passive. Other known refusals clear a stale native bot reaction when possible and queue the attributed fallback notice independently. Cleared/retired mapped copies are excluded. Source processing does not mark WhatsApp messages read.

When removal leaves no applied reaction, a fenced local plan step clears the obsolete refusal without calling Telegram. A subsequent reaction can retry immediately. Refusals currently routing a member reaction through the master remain cached. Cleanup and plan progress commit together and can resume without creating send effects or applied-reaction evidence.

Owner Telegram reactions select the newest changed reaction. Standard emoji and validated native custom-emoji equivalents can forward. An unresolved custom or paid reaction queues a temporary notice while preserving the previous WhatsApp reaction. Equivalents are account scoped and frozen before a retry. Confirmed equivalent changes are deduplicated; owner source echoes are suppressed only for the represented destination and private bot scope. Status archive reactions never forward to WhatsApp.

Reaction setters use frozen plans and fenced idempotent progress, as command-menu settings do. They set complete reaction state and can repeat after a lost response or process crash. They do not create ambiguous message-send effects. Fallback notices retain the normal durable send ledger and expiry. Migration 24 stores actor state, destination caches, frozen incoming/outgoing plans, confirmed echo evidence and custom-emoji equivalents.

Custom equivalents require exactly one grapheme and a Unicode pictograph, regional indicator or keycap component. The latest stable `github.com/clipperhouse/uax29/v2` release, v2.7.0, supplies Unicode 17 grapheme segmentation. Pictograph ranges come from the matching official Unicode 17 data, with its SHA-256 and license retained beside the generated table. This preserves the baseline's emoji validation rather than guessing from custom sticker IDs.

Acceptance fixtures cover actor removal/full snapshots, retained actors sharing a bot, member fallback/refusal caching, attributed notices, attachment primaries, missing targets, overlapping private IDs, unresolved custom emoji, frozen equivalents, equivalent deduplication, source echoes and recovery after provider acceptance before progress persistence. Adapter fixtures verify native setter/removal/custom-emoji payloads and safe transport retries. The provider releases were rechecked on 12 November 2026: OpenWA Go SDK v0.11.1 and go-telegram/bot v1.28.0 remain current stable releases.
