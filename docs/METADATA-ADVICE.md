# Metadata commands, permission guidance and reports

`control.Sync` implements owner `/sync` and master group permission Start links through native admission/dispatch in isolated fixtures. `metadata.Inspector` freezes missing-contact-bot and permission advice after the text/picture stages. `metadata.Reports` validates sealed completion inputs and delivers frozen summaries through the existing durable control replies. The [durable run coordinator](METADATA-RUNS.md) now supplies admission, discovery, retries/partial outcomes, source serialization, shared-contact fan-out/coalescing and persistent cron. Explicit `run` composes these capabilities after native identity and callback verification; diagnostic `serve` remains passive.

## Commands and grants

Master private `/sync`, `/sync all`, and bare `/sync` in management outside a topic retain their global scope. Explicit `/sync all` also works in management topics. A linked conversation refreshes only that conversation; a bound contact bot refreshes its contact even without a direct route. Child bots cannot request global work. Argument guidance, command addressing, private-owner validation, edited-command suppression and effective topic/whole-group routing retain the baseline rules. Foreign mapped replies cannot select another conversation.

Native source JSON, exact update keys and owner identity are revalidated in the claim transaction. The independent `sync_metadata` admission, complete acknowledgement plan and command expiry evidence commit together. Failure rolls everything back before a send. Acknowledgement recovery reuses the saved text/destination without queuing another request or following a later route change. Bound child-bot replies retain the original thread behavior, independently of the notifier context. Defaults remain 60 seconds for plain notices and 600 seconds for interactive notices.

Missing Change Group Info rights produce the original grant URL requesting `change_info+delete_messages+invite_users` through Telegram's group picker. Permission actions retain a 24-hour deadline and bind permanent account, OpenWA session, owner, WhatsApp group, Telegram mirror and return generation. The owner's `/start sync_…` must arrive in that exact group with its route/generation still current. Invalid/expired links produce the original scoped guidance without admitting work. A valid link queues that group's metadata check; normal native metadata checks determine the available rights. Ordinary private Start help remains unchanged.

## Missing contact bots and roster changes

After confirmed text/picture stages, inspection checks the private mirror and native membership of registered contact bots in the frozen WhatsApp roster. Owner/administrator/member statuses count as present. Restricted/left/banned statuses retain the original missing-bot treatment; definite 400 lookup refusals also count as absent, while other failures remain visible. Verified aliases select existing bindings; display numbers do not establish phone identities. Advice uses stored contact names or bot usernames and requires no WhatsApp mutation.

The complete inspection and its permission action commit together under account/claim/route/snapshot fencing. Saved inspections survive a new database consumer without new membership calls, changing buttons or generating a new grant. Roster-change evidence is captured with the source snapshot: canonical member IDs and administrator flags determine change; display labels and equivalent verified aliases do not cause a false roster change.

## Sealed completion notices

A `control-sync-report` job carries run/session identity, target-job IDs, original request-job IDs and safe failure hints for known failed targets. Its deduplication key is exactly `sync-finish:<run>`. Target jobs must belong to that account/run/session and be terminal; running/pending/uncertain work or unresolved sending/uncertain effects cannot become a completion. Successful targets also require confirmed text/picture stages and a stored inspection. The coordinator supplies complete target/request membership and persisted partial outcomes. Warning outcomes may retain incomplete stages but require resolved effects; confirmed updates, available advice, roster-change evidence and unavailable-picture counts remain reportable.

Updated-field counts come from confirmed metadata mutation receipts, excluding photo-ID read receipts and notice sends. Summary counts, text, buttons, all destinations and expiry choices commit atomically before delivery. Group/contact totals, unavailable-photo counts, missing-bot warnings and the original wording are retained. Warning counts include duplicates while text shows the first four distinct warnings. Buttons retain the first eight missing bots and first three permission links, with the original UTF-16 label budgets. Plain text splits at 3,800 UTF-16 units, retaining markup on each packet.

Original account-scoped sync requests supply destinations; reports cannot specify arbitrary private recipients. The default notifier remains management when the initiating request has no notifier. Equivalent bot/chat/thread destinations are deduplicated, including coalesced manual requests. Unchanged cron work stays quiet when there are no updated fields, warnings or roster changes; manual waiters still receive their report. A missing bot or hidden picture alone does not change this quiet rule.

Each destination/packet keeps an independent frozen key, target and receipt, including different bots with overlapping private chat IDs. Partial retries send only unconfirmed packets. Later roster/route changes cannot rewrite a prepared summary. Uncertain notice sends retain review state. Migration `00016_metadata_advice.sql` preserves inspections, scoped grant actions and report summaries alongside the existing control plans, observations and effect receipts; import/recovery must retain this evidence.
