# Repository Guidelines

Bifrost is being ported to Go on `port/golang`. The approved behavior contract is in `openspec/`. Preserve every current behavior except the approved conditional caption-clearing change and larger outgoing WhatsApp sticker budget. Linked-name formatting, source deletion choices and former-topic deletion are intentional.

## Structure and design

Use one Go module, `cmd/bifrost` for composition, capability-focused `internal/` packages, narrow consumer-defined interfaces, explicit dependency injection and provider adapters. See `docs/GO-IMPLEMENTATION.md`. PostgreSQL delivery persistence and a diagnostic runtime are implemented; SDK clients, explicit provider diagnostics and authenticated durable ingress are implemented. Ingress is opt-in. The fenced worker, initial routing and typed text-relay capabilities (formatting, frozen plans, scoped mappings and separate read receipts) are tested in isolation. Serve does not dispatch automatically until full workflows exist. Native source normalization and dispatcher wiring now run through the worker in isolated integration tests; see docs/DISPATCH.md. Complete runtime workflows and legacy import remain pending.

Use PostgreSQL with pgx/v5, explicit SQL/sqlc and Goose migrations. Alias evidence, contact profiles, copied mention tokens and roster snapshots are account-scoped and fenced; alias and bot-binding changes serialize together. Never derive a phone identity from a LID display number. See docs/IDENTITY-MENTIONS.md and docs/MENTION-PICKER.md for mention resolution, scoped picker controls, refusal notices and cleanup metadata; durable notice expiry and scoped clear handlers are tested through the worker (docs/TELEGRAM-CLEANUP.md). Former-inbox retirement is fenced and independently retryable (docs/INBOX-RETIREMENT.md); route and relay-plan writes must serialize with its permanent topic reservations. Conversation preference/read commands use atomic management admission and frozen confirmation plans (docs/OWNER-COMMANDS.md); preserve the legacy mode-selection rules and avoid re-applying preferences on notice retry. Ordinary Start activation/help and migration-gated command menus are tested (docs/STARTUP-CONTROLS.md); registration/Start never establish local API migration eligibility, and settings use a separate idempotent journal. Manual mirror transitions are tested (docs/MIRROR-TRANSITIONS.md); route moves/imports must respect pending topic-creation guards, and generic job skipping does not reconcile them. Native group selection and topic headers/actions are tested (docs/GROUP-PICKER.md); requests consume with route/confirmation commits, callbacks enforce full scope/expiry and the adapter preserves explicit false privacy constraints. Complete runtime composition remains pending. Use the OpenWA Go SDK and go-telegram/bot, strictly resolving latest stable releases and pinning exact versions when implementing their first real use. Verify current native features and API coverage. The gateway comes from the owner-maintained https://github.com/veryshyjelly/OpenWA fork at an explicitly reviewed commit; preserve its media/mention patches when updating the upstream base. Use the maintained Go SDK module github.com/veryshyjelly/OpenWA/sdk/go; its releases are independent of the gateway and other language SDKs. Do not silently replace libraries, drop features or float the gateway build on main.

For outgoing WhatsApp stickers in the Go port, use a 1,000,000-byte budget for the complete static or animated WebP, including metadata. The measured usable boundary is 1,048,558 bytes; 1,048,560 was rejected. Validate container structure as well as decoding, dimensions and timing; API acknowledgement alone does not prove rendering. Preserve Telegram limits. See docs/STICKER-LIMITS.md.

Use standard context, errors, net/http, log/slog and testing where they suffice. Run gofmt; prefer idiomatic Go naming and small packages over broad frameworks or generic repositories.

The metadata coordinator now composes durable admission, snapshots, resumable text/picture stages, permission advice/reports, target fan-out, partial outcomes/retry budgets, source serialization/coalescing and persistent timezone cron in isolated native worker fixtures; see docs/METADATA-RUNS.md. Final runtime composition and legacy import remain pending; do not start the scheduler or worker from diagnostic serve yet. Preserve the distinction between completed stages and complete refresh work. Freeze photo bytes before upload; cache evidence requires confirmed upload and native photo-ID observation receipts. Preserve uncertain photo uploads for explicit review. Reports require terminal account/run/session-bound target jobs, resolved effects and original request-job destinations; never announce unresolved work as complete.

Managed bot registration, encrypted credential lookup, explicit local API migration/webhooks and contact provisioning are implemented in isolated native fixtures (docs/MANAGED-BOTS.md). Registration and Start never establish migration eligibility. Preserve uncertain hosted logout for review, original encrypted tokens and scoped binding choices. Guarded native route repair preserves frozen content and requires no confirmed or uncertain packet; topic creation guards and receipts survive crash recovery (docs/ROUTE-REPAIR.md). The passive Status archive, frozen refresh batches, alias-scoped author mutes and versioned presented controls are implemented in isolated fixtures (docs/STATUS-ARCHIVE.md); source expiry and unmute never backfill skipped/cleared posts. Operational /status and /inbox controls, passive session events and explicitly enabled atomic failure-notice admission are tested in isolated fixtures (docs/OPERATIONAL-CONTROLS.md). Explicit topic inspection/reconciliation and the authenticated recovery CLI preserve guards, original receipts and scoped operator evidence (docs/TOPIC-RECONCILIATION.md); generic skip never releases unresolved creation ownership. The complete remaining-work checklist is docs/PORT-COMPLETION.md.
History choices, frozen batches, scoped holds and native attachment delivery are implemented in isolated fixtures (docs/HISTORY-ATTACHMENTS.md). Keep hash-addressed frozen bytes and original effect keys across retries; unknown sends cannot be adopted by history. The codec image includes pinned Pillow and an embedded Lottie renderer.

Legacy v1 archives have read-only WAL-aware validation and atomic PostgreSQL preparation in isolated fixtures (docs/LEGACY-IMPORT.md). Migration 31 retains exact immutable source evidence and encrypted configuration; incomplete checkpoints block startup readiness and job claims. Migration 32 projects original bot ciphertexts/Start state and account/bot/credential-scoped hosted-logout proof; native local GetMe is still required before eligibility. Never fabricate missing legacy effect requests/receipts or activate a prepared account early.
Mapped text/caption edits and independent refusal notices are tested in isolated native fixtures (docs/MESSAGE-CHANGES.md). Preserve saved presentation and cleared destinations; caption clearing depends on provider acceptance. Reactions, revocations, repair and final composition remain pending.
Scoped poll controls and source vote notices are tested (docs/POLL-CONTROLS.md). Freeze exact option texts, serialize selections per poll and update selection only after acceptance. Votes use an idempotent settings journal, so a crash can repeat the frozen selection without uncertain message sends.
Actor-specific native reactions are tested (docs/NATIVE-REACTIONS.md). Keep per-actor state and private bot scope, freeze custom equivalents, preserve unresolved custom reactions, prefer fresh attachment copies and use fenced idempotent setters. Native setters must not become uncertain message sends; fallback notices use independent send jobs. Explicit source commands and revocation choices remain pending.
Source revocation choices are tested (docs/REVOCATION-CHOICES.md). Tombstones prevent live/history resurrection; owner Keep/expiry preserve content, Delete affects only the selected destination, and refused cleanup cannot claim deletion or overwrite surviving content. Preserve permanent account scope, private bot/message scope, frozen copy cursors and unknown prompt sends.
Explicit source /react and /delete commands and authenticated management actions are tested (docs/SOURCE-ACTIONS.md). Require mapped Telegram replies in the correct scope, preserve frozen requests on retry and keep source actions independent of command expiry. A gateway delete acknowledgement alone cannot remove Telegram content or invent a revoke.


## Commands and tests

- `make check`: formatting, go vet, race-enabled Go tests, repository audit and Compose validation.
- `make spec-check`: strict OpenSpec validation (requires installed OpenSpec).
- `go test ./internal/<package>`: focused tests once implementations exist.
- `make configure`, then fill Telegram API credentials and run `make up`: complete isolated Compose setup with one PostgreSQL instance (separate app databases/users), Redis, OpenWA, Telegram API and Bifrost.

Package checks cover the implemented persistence/diagnostic slice, not full behavior parity. Port observable OpenSpec scenarios and historical fixtures into Go. Use real isolated PostgreSQL for persistence/concurrency tests. Cover duplicate events, retries, partial/uncertain delivery, owner checks, crash recovery and migration. No numeric coverage target is imposed.

## History and operational safety

The full TypeScript baseline, tests and original deployment exist at commit `checkpoint-typescript-baseline`. Historical operational docs and examples are in `docs/legacy/`; they require that checkout. Source and fixture links in OpenSpec point to the checkpoint. Use `git show checkpoint-typescript-baseline:<path>` before the checkpoint is pushed.

Keep private environments, SQLite databases, media, backups and Docker volumes intact. Never reset permanent BIFROST_ACCOUNT_ID, encryption keys, stable delivery keys or receipts. Preserve uncertain sends for explicit review. Do not start two runtimes against the live identity or perform a live cutover as part of preparation. Follow historical MOVING/RECOVERY instructions before identity import.

Keep commits focused with plain imperative subjects. Describe behavior, validation and remaining integration limits in PRs. Do not introduce new behavior without an OpenSpec change.
