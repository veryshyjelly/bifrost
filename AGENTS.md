# Repository Guidelines

Bifrost is a self-hosted Go WhatsApp–Telegram bridge. The approved behavior contract is in `openspec/`. Preserve every current behavior except the specified conditional caption clearing, larger outgoing WhatsApp sticker budget and verified-link fallback for definitively refused restricted native bot mentions. Linked-name formatting, source deletion choices and former-topic deletion are intentional.

## Structure and design

The explicit Go `run` lifecycle now composes every workflow, buffers authenticated ingress through restricted bot bootstrap, verifies native identities on restart, registers callbacks and starts the paced worker, metadata cron and Status refresh under a dedicated PostgreSQL ownership lock. Diagnostic `serve` remains passive. See docs/RUNTIME.md. Applied schema history and immutable retained-state evidence must remain compatible.  Local Telegram token-directory paths are permitted only within the Telegram archive role, with traversal/drive/link/alternate-stream rejection preserved.

Use one Go module, `cmd/bifrost` for composition, capability-focused `internal/` packages, narrow consumer-defined interfaces, explicit dependency injection and provider adapters. See `docs/GO-IMPLEMENTATION.md`. PostgreSQL delivery persistence and a diagnostic runtime are implemented; SDK clients, explicit provider diagnostics and authenticated durable ingress are implemented. Ingress is opt-in. The fenced worker, initial routing and typed text-relay capabilities (formatting, frozen plans, scoped mappings and separate read receipts) are tested in isolation. Diagnostic serve never dispatches; explicit run composes the full workflows. Native source normalization and dispatcher wiring now run through the worker in isolated integration tests; see docs/DISPATCH.md. See docs/PHONE-HOST.md for optional Termux setup and recovery guidance.

Use PostgreSQL with pgx/v5, explicit SQL/sqlc and Goose migrations. Alias evidence, contact profiles, copied mention tokens and roster snapshots are account-scoped and fenced; alias and bot-binding changes serialize together. Never derive a phone identity from a LID display number. See docs/IDENTITY-MENTIONS.md and docs/MENTION-PICKER.md for mention resolution, scoped picker controls, refusal notices and cleanup metadata; durable notice expiry and scoped clear handlers are tested through the worker (docs/TELEGRAM-CLEANUP.md). Former-inbox retirement is fenced and independently retryable (docs/INBOX-RETIREMENT.md); route and relay-plan writes must serialize with its permanent topic reservations. Conversation preference/read commands use atomic management admission and frozen confirmation plans (docs/OWNER-COMMANDS.md); preserve the retained mode-selection rules and avoid re-applying preferences on notice retry. Ordinary Start activation/help and migration-gated command menus are tested (docs/STARTUP-CONTROLS.md); registration/Start never establish local API migration eligibility, and settings use a separate idempotent journal. Manual mirror transitions are tested (docs/MIRROR-TRANSITIONS.md); route moves/imports must respect pending topic-creation guards, and generic job skipping does not reconcile them. Native group selection and topic headers/actions are tested (docs/GROUP-PICKER.md); requests consume with route/confirmation commits, callbacks enforce full scope/expiry and the adapter preserves explicit false privacy constraints. Explicit run composes these workflows; diagnostic serve remains passive. Use the OpenWA Go SDK and go-telegram/bot, strictly resolving latest stable releases and pinning exact versions when implementing their first real use. Verify current native features and API coverage. The gateway comes from the owner-maintained https://github.com/veryshyjelly/OpenWA fork at an explicitly reviewed commit; preserve its media/mention patches when updating the upstream base. Use the maintained Go SDK module github.com/veryshyjelly/OpenWA/sdk/go; its releases are independent of the gateway and other language SDKs. Do not silently replace libraries, drop features or float the gateway build on main.

For outgoing WhatsApp stickers, use a 1,000,000-byte budget for the complete static or animated WebP, including metadata. The measured usable boundary is 1,048,558 bytes; 1,048,560 was rejected. Validate container structure as well as decoding, dimensions and timing; API acknowledgement alone does not prove rendering. Preserve Telegram limits. See docs/STICKER-LIMITS.md.

Use standard context, errors, net/http, log/slog and testing where they suffice. Run gofmt; prefer idiomatic Go naming and small packages over broad frameworks or generic repositories.

The metadata coordinator now composes durable admission, snapshots, resumable text/picture stages, permission advice/reports, target fan-out, partial outcomes/retry budgets, source serialization/coalescing and persistent timezone cron in isolated native worker fixtures; see docs/METADATA-RUNS.md. Runtime composition is complete; diagnostic serve never starts the scheduler or worker. Preserve the distinction between completed stages and complete refresh work. Freeze photo bytes before upload; cache evidence requires confirmed upload and native photo-ID observation receipts. Preserve uncertain photo uploads for explicit review. Reports require terminal account/run/session-bound target jobs, resolved effects and original request-job destinations; never announce unresolved work as complete.

Managed bot registration, encrypted credential lookup, explicit local API migration/webhooks and contact provisioning are implemented in isolated native fixtures (docs/MANAGED-BOTS.md). Registration and Start never establish migration eligibility. Preserve uncertain hosted logout for review, original encrypted tokens and scoped binding choices. Guarded native route repair preserves frozen content and requires no confirmed or uncertain packet; topic creation guards and receipts survive crash recovery (docs/ROUTE-REPAIR.md). The passive Status archive, frozen refresh batches, alias-scoped author mutes and versioned presented controls are implemented in isolated fixtures (docs/STATUS-ARCHIVE.md); source expiry and unmute never backfill skipped/cleared posts. Operational /status and /inbox controls, passive session events and explicitly enabled atomic failure-notice admission are tested in isolated fixtures (docs/OPERATIONAL-CONTROLS.md). Explicit topic inspection/reconciliation and the authenticated recovery CLI preserve guards, original receipts and scoped operator evidence (docs/TOPIC-RECONCILIATION.md); generic skip never releases unresolved creation ownership. Current startup and recovery behavior is documented in docs/RUNTIME.md.
History choices, frozen batches, scoped holds and native attachment delivery are implemented in isolated fixtures (docs/HISTORY-ATTACHMENTS.md). Keep hash-addressed frozen bytes and original effect keys across retries; unknown sends cannot be adopted by history. The codec image includes pinned Pillow and an embedded Lottie renderer.


## Commands and tests

- `make check`: formatting, go vet, race-enabled Go tests, repository audit and Compose validation.
- `make spec-check`: strict OpenSpec validation (requires installed OpenSpec).
- `go test ./internal/<package>`: focused tests once implementations exist.
- `make configure`, then fill Telegram API credentials and run `make up`: complete isolated Compose setup with one PostgreSQL instance (separate app databases/users), Redis, OpenWA, Telegram API and Bifrost.

Package checks cover the composed Go capabilities, migration and recovery; live evidence is scoped in docs/RUNTIME.md. Preserve observable OpenSpec scenarios and established Go fixtures. Use real isolated PostgreSQL for persistence/concurrency tests. Cover duplicate events, retries, partial/uncertain delivery, owner checks, crash recovery and migration. No numeric coverage target is imposed.

## History and operational safety

Keep private environments, SQLite databases, media, backups and Docker volumes intact. Never reset permanent BIFROST_ACCOUNT_ID, encryption keys, stable delivery keys or receipts. Preserve uncertain sends for explicit review. Do not start two runtimes against the live identity. A rollback or host transfer requires quiescing writers and reconciling the latest paired-session and delivery state. Follow docs/PHONE-HOST.md when transferring an installation; preserve applied schema history and read-only retained-state protections.

Keep commits focused with plain imperative subjects. Describe behavior, validation and remaining integration limits in PRs. Do not introduce new behavior without an OpenSpec change.

Restricted native bot mentions use a fenced text-link fallback only after Telegram sendMessage returns definitive BOT_ACCESS_RESTRICTED. Verify the saved bot ID and username through the master in the original destination; never change bot access settings, sender, text or other entities. Keep the original request discarded and immutable, freeze a separate fallback effect and preserve unknown fallback sends for review. History review resumes its saved batch and original completed receipts. See docs/HISTORY-ATTACHMENTS.md.
